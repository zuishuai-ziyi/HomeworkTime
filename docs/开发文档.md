## 一、项目概览

### 1.1 定位

部署在学校希沃一体机（Windows x64）上的晚自习作业时间提示系统。三端组成：

| 端 | 形态 | 运行环境 | 主要职责 |
|---|---|---|---|
| 桌面客户端 | PyQt5 单进程 GUI | Windows x64、Python 3.10+ / 3.14 | 主窗口 / 悬浮球 / 配置窗口 / 托盘 / 心跳 + 配置轮询 / 提示音 |
| 服务端 | Node.js + Express | 宝塔面板、Node ≥ 18、MySQL 5.7+ / 8.0 | 后台管理 API + 客户端轮询 API + JWT 鉴权 + 业务配置持久化 |
| 管理前端 | Vue3 SPA | 与服务端同源托管（Express 直挂 / Nginx 反代） | 配置编辑 / 音频管理 / 用户管理 / 设备监控 / Token 管理 / 操作日志 |

### 1.2 三端架构

## 三、服务端

### 3.1 启动与开发命令

```bash
cd server
npm install              # 首次安装依赖（生产可用 --omit=dev）
npm run dev              # node --watch src/app.js（文件变更自动重启）
npm start                # node src/app.js（生产）

curl http://127.0.0.1:3000/api/health    # 健康检查
```

启动流程（`app.js#start`）：

1. `assertJwtSecretConfigured()`：检查 `JWT_SECRET`，生产未改默认值则 `process.exit(1)`。
2. `await ensure()`：幂等初始化默认数据（admin / 默认配置 / 占位 Token / 内置音频元数据）。
3. `app.listen(PORT, ...)`：监听 3000（默认）。
4. 注册 `SIGINT` / `SIGTERM` 优雅关闭（10 秒兜底强退）。

### 3.2 路由表

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| GET | `/api/health` | 无 | 健康检查 |
| POST | `/api/auth/login` | 无（IP 限速 10/分钟） | 登录，签发 12h JWT |
| GET | `/api/config` | JWT 或 `X-Client-Token` | 读取业务配置（含 version / updated_at / updated_by） |
| PUT | `/api/config` | JWT 或 `X-Client-Token` | 写入业务配置（`validateAndMerge` + version+1 + 审计） |
| GET | `/api/audio` | JWT | 列出音频元数据（内置在前，按 `is_builtin DESC, id ASC`） |
| POST | `/api/audio` | JWT | multer 上传 WAV（multer 100MB 上限）；同名覆盖；写审计 |
| DELETE | `/api/audio/:id` | JWT | 删除音频（内置拒绝 400）；写审计 |
| GET | `/api/users` | JWT | 列出管理员（不含 password_hash） |
| POST | `/api/users` | JWT | 创建管理员（bcrypt 10 轮） |
| PUT | `/api/users/:id` | JWT | 改用户名 / 密码 |
| DELETE | `/api/users/:id` | JWT | 删除（不能删自己 / 最后一个） |
| GET | `/api/client-token` | JWT | 查看当前客户端 Token |
| POST | `/api/client-token/reset` | JWT | 重置为新的 48 位 hex Token |
| GET | `/api/devices` | JWT | 设备列表（含 online 判定：心跳 ≤ 30 秒视为在线） |
| PUT | `/api/devices/:id` | JWT | 改教室名 `room_name`（≤ 128 字符） |
| GET | `/api/audit-logs?page=&page_size=` | JWT | 审计日志分页（page_size 1–100） |
| GET | `/api/client/config` | `X-Client-Token` | 客户端拉取业务配置 |
| POST | `/api/client/heartbeat` | `X-Client-Token` | 客户端心跳（按 `device_uuid` upsert；响应含已发布更新包信息 `update`） |
| GET | `/api/client/audio` | `X-Client-Token` | 列出音频（仅 filename / size / sha256 / is_builtin） |
| GET | `/api/client/audio/:filename` | `X-Client-Token` | 下载音频二进制（仅 `stored_path IS NOT NULL`） |
| GET | `/api/client/update/download` | `X-Client-Token` | 下载全量更新包 zip 二进制流（含 `X-Update-Sha256` / `X-Update-Size` 头） |
| POST | `/api/updates/upload` | JWT | 上传更新包并发布（multer zip 500MB 上限；仅保留最新一个包；写审计） |
| GET | `/api/updates/current` | JWT | 当前已发布更新包信息（不含 stored_path） |
| PUT | `/api/updates/current/effective-time` | JWT | 修改当前更新包生效时间（写审计） |

### 3.3 鉴权体系（`server/src/auth.js`）

三种 Express 中间件：

| 中间件 | 头部 | 适用接口 | 失败状态 |
|---|---|---|---|
| `requireAuth` | `Authorization: Bearer <jwt>` | 除 `/api/config` 外的后台管理接口 | 401 未提供 Token / 401 Token 无效或已过期 |
| `requireClientToken` | `X-Client-Token: <token>` | 客户端接口（`/api/client/*`） | 403 缺少客户端 Token / 403 客户端 Token 无效 |
| `requireAuthOrClientToken` | 任一上述 | `GET/PUT /api/config` | 缺失 → 401；任一校验失败分别回 401 / 403 |

JWT 默认 12h 过期；密钥通过 `process.env.JWT_SECRET` 注入；生产未配置强随机密钥时 `app.js` 拒绝启动。

### 3.4 数据库表结构（`server/sql/schema.sql`）

| 表 | 关键字段 | 备注 |
|---|---|---|
| `users` | `id, username(唯一), password_hash(bcryptjs), created_at, updated_at` | 后台管理员 |
| `config` | `id(单行=1), content_json(JSON), version, updated_at, updated_by(可为 null)` | 业务配置单行表 |
| `client_token` | `id(单行=1), token(唯一), updated_at` | 客户端共用 Token |
| `devices` | `id, device_uuid(唯一), device_name, room_name, ip, client_version, update_pending_version, last_heartbeat, last_config_version, created_at, updated_at` | 设备心跳与在线监控；`update_pending_version` 为已下载待生效的更新版本 |
| `audio_files` | `id, filename(唯一), stored_path(内置为 NULL), size, sha256, is_builtin, uploaded_by, created_at` | 内置 audio 不可删 |
| `client_update` | `id(单行=1), version, notes, stored_path, size, sha256, effective_time, published_at, uploaded_by` | 全量更新包单行表（仅保留最新一个包；`effective_time` 为客户端生效时间，上传时为空取当前时间=立即生效） |
| `audit_logs` | `id, user_id(可为 null), action, detail_json, created_at` | 操作日志（按 created_at DESC 查询） |

字符集统一 `utf8mb4_unicode_ci`；时间字段使用 `DATETIME`（默认 `CURRENT_TIMESTAMP`）。

### 3.5 环境变量（`server/.env.example`）

| 变量 | 默认值 | 必填（生产） | 说明 |
|---|---|---|---|
| `PORT` | `3000` | 否 | Node 监听端口 |
| `DB_HOST` | `127.0.0.1` | 否 | MySQL 主机 |
| `DB_PORT` | `3306` | 否 | MySQL 端口 |
| `DB_USER` | `root` | 否 | MySQL 用户名（生产建议不用 root） |
| `DB_PASSWORD` | 空 | **是** | MySQL 密码 |
| `DB_NAME` | `homework_time` | 否 | 数据库名 |
| `JWT_SECRET` | `homework-time-default-secret-change-me` | **是** | JWT 签名密钥；生产必须 `openssl rand -hex 32` |
| `NODE_ENV` | （未设） | 生产 `production` | `production` 时 `JWT_SECRET` 默认值会拒绝启动 |
| `CORS_ORIGIN` | （未设） | 否 | 逗号分隔白名单；未设则 CORS 全开 |
| `SERVE_UPLOADS_STATIC` | （未设） | 否 | 设为 `1` 时直挂 `/uploads/audio`，仅本地调试用 |

### 3.6 幂等初始化（`server/src/utils/seed.js`）

启动时 `await ensure()` 一次性完成：

1. 无用户 → 插入 `admin / admin123`（bcrypt 10 轮）；打印「请立即修改密码」警告。
2. 无配置 → 读 `default_config.json`（去掉 `_comment` 占位键），写入 `config(id=1, version=1)`。
3. 无 Token → 写入占位 `CHANGE_ME_DEFAULT_TOKEN`。
4. 无内置音频 → 写入 `near.wav` 与 `end.wav`（`stored_path / size / sha256` 全 NULL，`is_builtin=1`）。

所有操作「已有则跳过」，可重复执行。

### 3.7 校验器冒烟测试

```bash
cd server
node src/smoke_test.js          # 不依赖数据库，校验 validate.js 全部路径
```

覆盖：默认配置通过校验、缺省字段默认值填充、非法 HH:MM、透明度越界、subjects 数量、start==end、科目重叠、科目超出晚自习范围、跨天配置、起止相等、未知顶层字段、allow_local_edit 非布尔、非对象输入、非法音频文件名等。

### 4.3 接口封装（`server/web/src/api/index.js`）

所有接口走 `src/api/http.js` 的 axios 实例：

- 基础：`baseURL='/api'`、`timeout=20000`。

- `logout()`：清 state + localStorage。

### 5.3 启动流程与状态机

启动序列（`app.main.run()`）：

1. `setup_logging()`：按天滚动本地日志。
2. `QApplication(sys.argv)`。
3. `SingleInstance()`：非 principal → `notify("show")` 唤醒既有实例后退出。
4. `LocalConfig()`：三级加载并原子写 `local_config.json`；首次启动生成 `device_uuid`。
5. `_needs_guide()` 判定 → `_run_guide_if_needed()` 弹引导（接受 → 写 URL/Token；跳过 → 写 `guide_dismissed=True`）。
6. `autostart.set_autostart(local_config.autostart)`。
7. `AppController(...)`：构造主窗口 / 悬浮球 / 托盘 / 网络同步定时器；接好信号；立即执行一次 `_tick()` 与一次网络 tick。
8. `app.exec_()` 进入事件循环；`controller.shutdown()` 退出时清理。

窗口状态机（`_sync_windows(state)`，每秒触发）：

| 状态 | 主窗口 | 悬浮球 |
|---|---|---|
| 晚自习内 & 用户未主动关闭 | 置顶显示 | 隐藏 |
| 晚自习内 & 用户已点 × | 隐藏 | 置顶显示 |
| 晚自习外 & 用户没打开主窗口 | 隐藏 | 置底显示 |
| 晚自习外 & 用户打开了主窗口 | 置底显示（带「不在晚自习时间」） | 置底显示 |

提示音调度（`scheduler.get_sound_actions(cfg, state, t, prev_key)`）：

- 当前科目段剩余秒数 `> 0` 且 `≤ sound.near_seconds` → 每秒播放 `near.wav`。
- 上一 tick 仍在科目段、本 tick 已跨越结束点 → 播放一次 `end.wav`。
- 切换科目段时 `prev_key` 自动变化，结束音不会重复触发。

### 5.4 配置双轨体系

#### 5.4.1 业务配置（服务器权威）

| 文件 | 同步角色 |
|---|---|
| `cache/business_config.json` | 缓存（含顶层 `version` 字段）；ApiClient `apply_config` 后整行写回 |
| `app/default_config.json` | 内置兜底（与 `server/src/default_config.json` 完全一致） |

读取顺序（`AppConfig.load()`）：缓存 > 内置；缺失字段用内置默认深合并填充。

写入链路（业务配置单一数据源 = 服务器）：

- 在线：`PUT {base_url}/api/config`（`X-Client-Token`），服务端校验 + `version+1` + 审计；成功 → `apply_config()` 立即使 UI/调度器生效。
- 离线：网络异常 / 超时 → `save_pending(config)` 追加到 `cache/pending_updates.json` 队列；提示「已离线保存，联网后自动同步」。
- HTTP 4xx/5xx（Token 无效、校验失败）：弹窗提示，**不入队**。

补传时机（`AppController._network_tick()`）：

- 只要心跳成功（在线）且队列非空就尝试补传；幂等。
- 失败保留队列顺序，下次 tick 重试；失败日志最多每 5 分钟一条。

#### 5.4.2 本机配置（`local_config.json`，不同步服务器）

三级加载顺序（`LocalConfig.load()`）：

1. 运行目录已有 `local_config.json` → 直接读取（仅保留白名单键）。
2. 否则存在打包预设 `local_config.preset.json` → 以其为底初始化（仅白名单键；空字符串字段回落默认值；`ball_pos` 恒为 `null`）。
3. 否则参照 `local_config.example.json`（去除 `_comment`）+ 默认值。

均会生成 `device_uuid` 并原子写（临时文件 + `os.replace`）到运行目录。

### 5.5 提示音三态解析（`AudioPlayer._resolve_path`）

| 优先级 | 位置 | 说明 |
|---|---|---|
| 1 | 绝对路径 | `wav_name` 为绝对路径且文件存在 → 直接使用 |
| 2 | 下载缓存 | `runtime_dir()/cache/sounds/<name>`（运行期从服务端下载的覆盖版） |

服务端 sha 与本地不一致时 `ensure_audio` 触发下载；下载后二次 sha256 校验失败 → 删除文件回退内置。

### 5.6 单实例（`app/single_instance.py`）

### 5.7 日志（`app/logger.py`）

- 目录：`runtime_dir()/logs`（打包后与 exe 同目录）；可用环境变量 `HOMEWORKTIME_LOG_DIR` 覆盖为绝对路径。

### 5.9 打包流程

```powershell
cd client
# 1) 从 local_config.example.json 复制一份 local_config.preset.json（仓库不含此文件，已 .gitignore）
#    并填好 server_base_url / client_token（免引导）；若文件缺失 build.py 会走「未填写确认」分支
# 2) 打包
python build.py                  # 等价于双击 build.bat
```

`build.py` 流程：

1. 读 preset，检测 URL / Token 是否填写；未填写 → 警告并要求 `y` 确认（产物首次运行会弹引导）。
2. 检测 PyInstaller 可用性；缺失时打印 `pip install pyinstaller` 指引。
3. 以 `client/` 为 cwd 调用 PyInstaller：

   ```text
   pyinstaller --noconfirm --noconsole --name HomeworkTime --onedir ^
     --add-data "resources;resources" ^
     --add-data "app\default_config.json;app" ^
     --add-data "local_config.preset.json;." ^
     --exclude-module tkinter --exclude-module unittest ^
     --exclude-module pydoc --exclude-module doctest ^
     main.py
   ```

4. 产物：`client/dist/HomeworkTime/HomeworkTime.exe`。
5. 自动产出全量更新包：`client/dist/HomeworkTime_<版本>.zip`（zip 根级 = 应用文件 + `update_manifest.json` 版本清单），供管理端「更新管理」页上传发布。

打包要点：

- `resources/` 通过 `--add-data` 打进 `_MEIPASS/resources`；`resource_path()` 在 PyInstaller 下自动走 `sys._MEIPASS`。
- `local_config.preset.json` 打进 `_MEIPASS` 根；目标机首次运行据此在 exe 同目录生成 `local_config.json`。
- `local_config.preset.json` **不入库**（`.gitignore`）；新克隆的仓库应先 `copy local_config.example.json local_config.preset.json` 再按需填写真实地址/Token。
- 不要把 `local_config.json` / `cache/` / `logs/` 打进包。

### 5.10 远程更新（`app/updater.py`）

全量包替换式更新，支持**延迟更新**（管理端与学校端不同时在线：客户端上线后首次心跳即发现新版本）。

数据通路：

```
管理端「更新管理」上传 zip ──▶ client_update 表（单行，仅保留最新一个包）
                                      │
客户端心跳响应 update 字段 ◀──────────┘
        │
        ▼
Updater.evaluate() ──▶ 后台线程：流式下载 package.zip → sha256 校验
        │              → 解压 staging/（校验 zip 根级含 HomeworkTime.exe）
        ▼
maybe_apply()（每秒 tick）──▶ 到 effective_time 且非晚自习
        │
        ▼
生成 update.bat + applied.json ──▶ 拉起 bat ──▶ 宿主进程退出
        │
        ▼
bat：等待旧进程退出（≤30s，超时 taskkill）→ 旧文件移 backup/ →
     staging/ 移入程序目录 → 校验 exe 缺失则回滚 backup → 重启 exe
        │
        ▼
新版本 startup_check()：版本匹配 → 清理暂存并记 last_applied_sha；
                       不匹配 → fail_count+1（3 次后暂停该包自动应用）
```

关键设计：

- **时机判定**（`should_apply` 纯函数）：status==ready 且 fail_count<3 且 `now >= effective_time` 且不在晚自习时段；到点时正处晚自习则顺延至晚自习结束后下一次 tick 执行。
- **用户数据保留**：更新包只含应用文件（exe / `_internal` 等）；替换只针对包内顶层条目，`local_config.json` / `cache/` / `logs/` 天然不动。
- **bat 由客户端运行时生成**（不打包固定），升级脚本逻辑可随版本演进；内容纯 ASCII + mbcs 编码 + 路径尽量转 8.3 短路径。
- **防循环**：`last_applied_sha` 短路（同一 sha 的包不再重复安装，兼容服务器 version 标签与包内 manifest 不一致的场景）；应用失败计数 3 次上限。
- **下载不阻塞心跳**：`download_update` 用独立 `requests.get(stream=True)`，不占 `ApiClient._net_lock` 与 session。
- 仅 Windows（`os.name == "nt"`）执行应用动作；开发机 / CI 安全跳过。
- 更新状态持久化在 `cache/update/update_state.json`（status: idle/pending/downloading/ready/failed），进程重启可恢复。

与管理端配合：

- 发布：`POST /api/updates/upload`（version + notes + effective_time，为空=立即生效）；
- 改期：`PUT /api/updates/current/effective-time`（客户端下一次心跳感知）；
- 观测：设备监控页「待更新」列 = 心跳上报的 `update_pending_version`。

### 6.4 新增界面取色规则

- 需要主操作按钮、激活态、品牌色 → 用 `#0077B6`（或变量 `bright-teal-blue`）。
- 需要背景 / 卡片底色 → 用 `#CAF0F8`（浅）或 `#023E8A`（深，半透明）。
- 需要边框 / 描边 → 用 `#90E0EF`（主）/ `#ADE8F4`（次）。
- 需要警示 / 错误态 → 用与主题不冲突的红色（`#C0392B` / `#DC2626`）；不要引入与主题冲突的新颜色。

## 七、配置契约

业务配置契约是客户端模型、服务端校验、后台表单的唯一数据来源。任何字段变化都必须 **同步** 以下 6 处：

| 位置 | 文件 |
|---|---|
| 客户端 JSON Schema | `client/app/config_schema.json`（draft-07） |
| 服务端 JSON Schema | `server/src/config.schema.json`（draft-07） |
| 客户端内置默认 | `client/app/default_config.json` |
| 服务端内置默认 | `server/src/default_config.json` |
| 数据库初始 INSERT | `server/sql/schema.sql`（`config` 表初始 `content_json`） |
| 字段含义文档 | `docs/配置说明.md` 第二章 |
| 校验逻辑 | `server/src/utils/validate.js` |
| 客户端表单校验 | `client/app/windows/config_window.py` 的 `validate_subjects` 等纯函数 |
| 开发者权威文档 | `docs/开发文档.md` 第七章（本节） |
| 变更记录 | `docs/开发文档.md` 第十章 |

字段约束详见 `docs/配置说明.md` 与 `server/src/utils/validate.js#validateAndMerge`，包括：

- 未知顶层字段 → `未知配置项: <key>`。
- 起止时间相同 → `晚自习起止时间相同：结束时间不能等于开始时间`。
- 科目时间段重叠 / 越界 / `start == end` → 拒绝。
- 透明度范围 0.2–1.0、`near_seconds` 范围 1–3600 整数、音频文件名 `^[A-Za-z0-9._-]+\.wav$`。
- `theme` 三键必须 `^#[0-9A-Fa-f]{6}$`（服务端归一化为大写；客户端 `normalize_theme` 对脏值兜底默认色板）。
