# 部署说明

> 适用版本：HomeworkTime v0.1
> 客户端：希沃一体机（Windows x64，Python 3.x）
> 服务端：宝塔面板 + Node.js 18+ + MySQL 5.7 / 8.0

---

## 一、服务器要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux（宝塔面板支持的系统：CentOS 7+、Ubuntu 20+、Debian 11+ 等） |
| 宝塔面板 | 任意现行版本 |
| Node.js | ≥ 18.0.0（`server/package.json` 中 `engines.node`） |
| MySQL | 5.7+ / 8.0（要求 JSON 列与 `utf8mb4_unicode_ci`） |
| 磁盘 | 建议 ≥ 5 GB 可用（日志、音频上传、构建产物） |
| 内存 | 建议 ≥ 1 GB |
| 端口 | 3000（仅本机 Node 监听，不对公网开放）；80 / 443 对公网 |

---

## 二、服务端部署步骤

### 2.1 上传项目

将整个 `server/` 目录上传到服务器，宝塔面板的「文件」或 `scp` 均可。建议目录：

```text
/www/homework_time/
├─ src/                  # Express 后端源码
├─ web/                  # Vue3 后台源码（构建前的）
│   └─ dist/             # 构建产物（构建后才有）
├─ uploads/
│   └─ audio/            # 音频上传目录（运行时自动创建）
├─ sql/
│   └─ schema.sql        # 建库建表 + 初始数据
├─ package.json
└─ package-lock.json
```

### 2.2 安装 Node.js 依赖

```bash
cd /www/homework_time
npm install --omit=dev   # 或：npm install --production
```

依赖列表（`server/package.json`）：

| 包 | 版本 | 用途 |
|---|---|---|
| express | ^4.19.2 | Web 框架 |
| mysql2 | ^3.11.0 | MySQL 连接池 |
| jsonwebtoken | ^9.0.2 | JWT 签发 / 校验 |
| bcryptjs | ^2.4.3 | 密码哈希 |
| multer | ^1.4.5-lts.1 | 文件上传（音频） |
| cors | ^2.8.5 | 跨域 |

### 2.3 创建数据库

#### 方式一：宝塔面板「数据库 → 添加数据库」

- 数据库名：`homework_time`
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_unicode_ci`
- 用户名 / 密码：自定（建议不要用 `root`）

然后进入「phpMyAdmin → 导入」选择 `sql/schema.sql` 整段执行。

#### 方式二：命令行

```bash
mysql -u root -p < /www/homework_time/sql/schema.sql
```

> `schema.sql` 顶部自带 `CREATE DATABASE IF NOT EXISTS \`homework_time\`` 与 `USE \`homework_time\``，可独立执行。

#### ⚠️ 首次部署后必须立即做的事

`schema.sql` 末尾内置了**演示用数据**，**仅用于首次部署测试**，生产环境上线前必须：

1. 登录后台 → 「用户管理」修改 `admin` 的密码（默认 `admin / admin123`）。
2. 登录后台 → 「客户端 Token」→ 「重置」生成新 Token，并把新 Token 填入所有客户端的引导窗口。

未及时改密码 / 重置 Token 会导致任意拿到地址的人都能进入后台或冒名心跳。

#### 存量库升级（已部署过旧版本，2026-09-25 远程更新功能）

`schema.sql` 为全新建库脚本（含 DROP TABLE）。**已运行的旧库**请勿重复执行，只需在 phpMyAdmin / mysql 中执行以下增量 SQL：

```sql
USE homework_time;

-- 设备表新增「已下载待生效的更新版本」字段（心跳上报，NULL=无）
ALTER TABLE `devices`
  ADD COLUMN `update_pending_version` VARCHAR(32) NULL
    COMMENT '已下载待生效的更新版本 (心跳上报, NULL=无)'
    AFTER `client_version`;

-- 全量更新包单行表（仅保留最新一个包）
CREATE TABLE IF NOT EXISTS `client_update` (
  `id`             INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `version`        VARCHAR(32)  NOT NULL,
  `notes`          VARCHAR(500) NULL,
  `stored_path`    VARCHAR(255) NOT NULL,
  `size`           BIGINT UNSIGNED NOT NULL,
  `sha256`         CHAR(64)     NOT NULL,
  `effective_time` DATETIME     NOT NULL,
  `published_at`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `uploaded_by`    INT UNSIGNED NULL,
  `created_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='客户端全量更新包 (单行, 仅保留最新)';
```

#### 存量库业务配置补 theme 键（2026-09-25 窗口主题色功能）

旧库 `config.content_json` 中没有 `theme` 字段。客户端有默认色板兜底不会报错，但管理端首次保存前「配置编辑」页不会显示当前主题色，建议执行一次 UPDATE 补齐：

```sql
USE homework_time;

UPDATE `config` SET `content_json` = JSON_MERGE_PATCH(
  `content_json`,
  JSON_OBJECT('theme', JSON_OBJECT(
    'card', '#023E8A', 'accent', '#0077B6', 'timeline', '#03045E'))
)
WHERE `id` = 1
  AND JSON_EXTRACT(`content_json`, '$.theme') IS NULL;
```

#### 存量库升级（2026-09-26 短链服务配置保存）

`schema.sql` 已新增 `sink_settings` 单行表。已运行的旧库只需补执行：

```sql
USE homework_time;

-- Sink 短链服务配置单行表（服务地址 + API Key，管理端「短链服务设置」写入）
CREATE TABLE IF NOT EXISTS `sink_settings` (
  `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `sink_url`   VARCHAR(255) NULL                    COMMENT 'Sink 服务地址 (http(s)://host[:port],hostname 即短链域名)',
  `api_key`    VARCHAR(255) NULL                    COMMENT 'Sink Bearer 令牌 (NUXT_SITE_TOKEN 或 sk_ 开头 API Key, 明文)',
  `updated_at` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `updated_by` INT UNSIGNED NULL                    COMMENT '最近一次修改者 user.id',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='Sink 短链服务配置 (单行)';

INSERT INTO `sink_settings` (`id`) VALUES (1);
```

执行后在管理端「一键安装 → 短链服务设置」保存一次服务地址与 API Key 即可生效。

### 2.4 配置环境变量

服务端口、数据库连接、JWT 密钥全部通过环境变量传入（见 `server/src/db.js` 与 `server/src/auth.js`）。

| 变量 | 默认值 | 必填（生产） | 说明 |
|---|---|---|---|
| `PORT` | `3000` | 否 | Node 监听端口 |
| `DB_HOST` | `127.0.0.1` | 否 | MySQL 主机 |
| `DB_PORT` | `3306` | 否 | MySQL 端口 |
| `DB_USER` | `root` | 否 | MySQL 用户名 |
| `DB_PASSWORD` | `""` | **是** | MySQL 密码 |
| `DB_NAME` | `homework_time` | 否 | 数据库名 |
| `JWT_SECRET` | `homework-time-default-secret-change-me` | **是** | JWT 签名密钥；**生产必须使用强随机值**（如 `openssl rand -hex 32`） |

#### `.env` 配置（项目内置 dotenv）

项目已自带 `dotenv` 依赖。复制 `server/.env.example` 为 `server/.env`，按需修改后启动即可生效；也可直接在宝塔「Node 项目」管理器的「环境变量」表单中填写（优先级：进程环境变量 > `.env`）。

```text
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=your_db_user
DB_PASSWORD=your_db_password
DB_NAME=homework_time
JWT_SECRET=<node -e "console.log(require('crypto').randomBytes(32).toString('hex'))" 生成>
```

> 启动脚本会先 `try { require('dotenv').config() }`（不存在的 `.env` 时安全跳过）。各变量含义见 `server/.env.example`。

### 2.7 Nginx 反代 + 静态托管

#### 创建静态站点

在宝塔「网站 → 添加站点」中：

| 字段 | 值 |
|---|---|
| 域名 | `admin.example.com`（按需） |
| 根目录 | `/www/homework_time/web/dist`（构建产物所在目录） |
| PHP | 纯静态 |
| 数据库 | 不创建 |

#### Nginx 配置（站点「设置 → 配置文件」）

将后端 `/api` 与 `/uploads` 反代到本机 Node 进程（`127.0.0.1:3000`）。示例：

```nginx
server {
    listen 80;
    server_name admin.example.com;   # 替换为实际域名

    # 静态资源（Vue 后台构建产物）
    root /www/homework_time/web/dist;
    index index.html;

    # 更新包上传上限（管理端 zip 可达数百 MB；默认 1m 会导致 413）
    client_max_body_size 600m;

    # 简易 gzip（按需）
    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    # 后端 API 反代
    location /api/ {
        proxy_pass         http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        # 普通接口秒级返回；更新包下载为长连接大文件，放宽读超时
        proxy_read_timeout    600s;
    }

    # 音频上传目录直挂（与 Node 同步服务）
    location /uploads/ {
        proxy_pass         http://127.0.0.1:3000;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
    }

    # SPA hash 路由：所有未匹配到的路径都返回 index.html（hash 模式下不依赖 try_files）
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

> **关于 SPA hash 路由**：本项目后台使用 `vue-router` 的 `createWebHashHistory()`（URL 带 `#/...`），所以实际上**不需要** `try_files ... /index.html`；但加上无害，可兼容未来切换为 history 模式。

#### HTTPS / Let's Encrypt

在宝塔「网站 → 设置 → SSL → Let's Encrypt」一键申请并开启「强制 HTTPS」。申请前请确保域名已正确解析到服务器 IP。

> 具体域名 / 证书 / 备案信息以部署时确认为准；本文不给出示例生产域名。

### 2.8 防火墙 / 安全组

| 端口 | 用途 | 是否对公网 |
|---|---|---|
| 80 / 443 | HTTP / HTTPS（Nginx） | 是 |
| 3000 | Node 直连端口 | **否**（仅本机 `127.0.0.1`） |
| 3306 | MySQL | **否**（仅本机） |
| 22 | SSH | 按运维需要（建议仅运维 IP 白名单） |

宝塔「安全」中放行 80/443；3000 与 3306 不放行。系统防火墙 `firewalld` / `ufw` / `iptables` 同样仅放行对外服务端口。

```bash
# 期望: {"ok":true,"time":"2026-09-18T..."}
```

## 三、客户端部署（希沃一体机）

> 支持源码运行与 PyInstaller 打包（见下文 3.5）。希沃一体机默认 Windows x64。

### 3.1 安装 Python 与依赖

```powershell
# 1. 安装 Python 3.10+（勾选 Add to PATH；如 3.14 也支持，见 plan.md）
#    https://www.python.org/downloads/

# 2. 进入项目目录
cd C:\path\to\HomeworkTime\client

# 3. 安装依赖（仅 PyQt5 + requests）
pip install -r requirements.txt
```

`requirements.txt`：

```text
PyQt5==5.15.11
requests
```

### 3.2 首次运行 + 引导

```powershell
cd C:\path\to\HomeworkTime\client
python main.py
```

- 若 `local_config.json` 缺失或 `server_base_url` / `client_token` 为空 → 弹出「首次使用引导」窗口：
  - 「服务器地址」填 `https://admin.example.com`（或内网地址，如 `http://192.168.1.10:3000`）；
  - 「客户端 Token」填后台「客户端 Token」页面下发的 48 位十六进制字符串；
  - 「测试连接」会显示「✓ 连接成功（配置版本 vN）」；
  - 「保存并进入」即可。
- 也可点「跳过（离线模式）」，客户端使用内置默认业务配置运行（所有配置修改会写入离线队列）。

### 3.3 开机自启

两种方式任选其一：

1. **托盘勾选**：客户端运行时，系统托盘右键 → 「开机自启」打勾；客户端会写入：

   ```text
   HKCU\Software\Microsoft\Windows\CurrentVersion\Run\HomeworkTime
   "(pythonw.exe 或 python.exe 的绝对路径)" "C:\path\to\client\main.py 的绝对路径"
   ```

2. **直接调用 / 注册表**：源码运行期外，可手动通过「regedit」写入同名键值；或运行 `python -c "from app.autostart import set_autostart; set_autostart(True)"`（在 `client/` 目录下）。

> `autostart.py` 优先选择 `pythonw.exe`（避免开机时弹出黑色控制台窗口）；若不存在则退回 `python.exe`。

### 3.4 日志位置

```text
C:\path\to\HomeworkTime\client\logs\app_YYYY-MM-DD.log
```

- 按天滚动；保留最近 30 天（默认，可在 `logger.setup_logging(keep_days=N)` 中调整）；
- 通过环境变量 `HOMEWORKTIME_LOG_DIR` 可改为绝对路径；
- 日志**仅本地留存，不上报服务器**。

### 3.5 打包 EXE（PyInstaller + 打包预设）

推荐 **onedir 单目录**打包（启动快、希沃一体机友好）：整个 `dist/HomeworkTime/` 文件夹拷贝到目标机即可运行。

#### 第一步：填写打包预设

> **`client/local_config.preset.json` 不在仓库中**（已在 `.gitignore` 覆盖 + 从 Git 索引移除），本机需先从 `local_config.example.json` 复制一份并重命名为 `local_config.preset.json`（仅本机使用、绝不上传服务器），再按需填写真实地址与 Token。若仓库中无该文件，build.py 会走「未填写确认」分支并给出明确提示，不会崩溃。

复制并编辑：

```powershell
cd client
copy local_config.example.json local_config.preset.json
# 编辑 local_config.preset.json，填好：
#   server_base_url：服务器实际地址，如 https://admin.example.com 或 http://192.168.1.10:3000（含协议与端口，不要带尾斜杠）
#   client_token：后台「客户端 Token」页签发的 48 位十六进制 Token
```

> 若两项留空打包：产物首次运行会弹出「首次使用引导」窗口，需在目标机手动填写地址与 Token（可跳过进入离线模式）。建议打包前统一填好，实现「免引导」分发。

#### 第二步：打包

```powershell
cd client
python build.py          # 或直接双击 build.bat
```

脚本（仅标准库）执行以下检查后调用 PyInstaller：

1. 检查预设是否已填写——未填写则**警告并要求输入 `y` 确认**（提示产物首启会弹引导）；
2. 检查 PyInstaller 是否可用——缺失时打印 `pip install pyinstaller` 安装指引（不会自动安装）；
3. 以 `client/` 为工作目录打包，等价于：

```text
pyinstaller --noconfirm --noconsole --name HomeworkTime --onedir ^
    --add-data "resources;resources" ^
    --add-data "app/default_config.json;app" ^
    --add-data "local_config.preset.json;." ^
    --exclude-module tkinter --exclude-module unittest --exclude-module pydoc ...
    main.py
```

打包要点：

- `--add-data "resources;resources"` 把内置音频 `near.wav`/`end.wav` 与图标打进包（`resource_path()` 在 PyInstaller 下自动走 `sys._MEIPASS`）；
- `local_config.preset.json` 打进包（`_MEIPASS` 根），目标机首次运行据此在 **exe 同目录**自动生成 `local_config.json`：`device_uuid` 自动生成、`ball_pos` 保持 `null`、缺失字段用默认值补齐、`_comment` 等说明键不会写入；
- 不要把 `local_config.json` 打进包——它是用户态配置，由客户端首次运行生成；
- 不要把 `cache/`、`logs/` 打进包——它们是运行期产物。

打包完成后脚本会**自动产出全量更新包**：`client/dist/HomeworkTime_<版本>.zip`（zip 根级 = 应用文件 + `update_manifest.json` 版本清单，版本号取自 `client/app/version.py`）。

#### 第三步：分发

`client/dist/HomeworkTime/` 整个文件夹拷贝到目标机，双击 `HomeworkTime.exe` 即可。首次启动：

- 打包预设已填好 → 自动以预设地址/Token 生成本机 `local_config.json`，**免引导**；
- 未填好 → 弹出首次引导窗口。

> 单文件 `--onefile` 也可用（启动稍慢、分发更简洁），但 onedir 启动快、便于排查，推荐默认使用。

#### 第四步（可选）：远程推送更新

1. 登录管理端 → 「更新管理」→ 上传 `HomeworkTime_<版本>.zip`，填写版本号（从文件名自动带出）与生效时间（默认立即；建议选非晚自习时段，如上午 8:00）→ 「上传并发布」；
2. 各教室设备联网后首次心跳即自动后台下载（离线设备上线后补下——延迟更新）；到生效时间自动替换并重启（正处晚自习则顺延至晚自习结束后执行）；
3. 「设备监控」页「待更新」列可观察各设备的待生效版本，「客户端版本」列变为新版本号即表示更新完成；
4. 回滚 = 重新上传旧版本 zip 并发布（服务端仅保留最新一个包）。

#### 第五步（可选）：一键安装分发

适合首次部署 / 重装时的批量安装：不再手工拷贝文件夹，而是在目标机执行一条 PowerShell 命令完成安装。

1. 登录管理端 → 「一键安装」→ 上传 `HomeworkTime_<版本>.zip`（`build.py` 产物可直接复用），填写安装目录（默认 `C:\HomeworkTime`）与**客户端服务器地址**（目标机访问服务端用的地址，默认带出当前浏览器地址）；「写入连接配置」开启时脚本按「客户端 Token」页当前值内嵌 Token，首启免引导；
2. 上传完成后点「安装命令」，复制形如下面的命令，在目标机 PowerShell（建议管理员身份）中执行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -Command "irm 'http://<客户端服务器地址>/api/install/s/<slug>' | iex"
   ```

   脚本会自动：结束旧进程 → 下载 zip → 解压到安装目录 → 写 `local_config.json` → 启动客户端（开机自启由客户端自行注册）。可重复执行覆盖安装。
3. 命令太长可点「短链」接自托管 Sink 短链服务（填 Sink 地址 + API Key，可选自定义 slug），生成 `irm '<短链>' | iex` 形式的短命令；勾选「保存到服务器」（或先在工具栏「短链服务设置」中保存）后，服务地址与 API Key 存入服务端 `sink_settings` 表，所有管理端浏览器共享、下次免输入，页面仅脱敏回显 Key；
4. 安全须知：脚本/安装包下载地址中的 16 位随机 slug 即访问凭据，请勿外传；某批次泄露可在列表中「停用」（立即 404）或删除。

## 五、常见问题 FAQ

### 5.1 服务端启动报错：数据库连不上

- 检查 `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME`；
- 宝塔「数据库」页确认该用户已授权 `homework_time` 库（建议给全部权限，部署侧最小化为 `SELECT / INSERT / UPDATE / DELETE`）；
- MySQL 8.0 默认 `caching_sha2_password`，mysql2 客户端需要兼容版本（当前 `mysql2 ^3.11.0` 已支持）；
- 确认 3306 已监听本机：`ss -tlnp | grep 3306`。

### 5.2 前端登录返回 401 / 后台 403

- 401 多半是 `JWT_SECRET` 与签发时不一致（部署期间改过）；让用户重新登录即可；
- 403 `缺少客户端 Token`：客户端未填写 / 填错 `X-Client-Token`；后台「客户端 Token」页查看当前 Token 值并重新填写。

### 5.3 客户端「不在线」

- 「设备监控」页 `online` 为 `false`：客户端心跳超过 30 秒未到。
- 排查清单：
  1. 客户端到服务器的网络（`curl http://<host>:3000/api/health`）；
  2. Nginx 反代是否放行 `/api/`；
  3. 客户端的 `server_base_url` 是否正确（含协议与端口）；
  4. 客户端 `client_token` 是否与服务端 `client_token` 表一致（后台「客户端 Token」页核对）；
  5. 客户端 `local_config.json` 是否被改过（例如手动改为空）；
  6. 客户端日志 `logs/app_YYYY-MM-DD.log` 中是否持续打印 `网络 tick 心跳异常` 或 `请求返回 HTTP 403`。

### 5.4 音频下载失败

- 「音频管理」页 `near.wav` / `end.wav` 显示有 `stored_path` 但客户端下载 404：检查物理文件是否存在（`ls /www/homework_time/uploads/audio/`）；
- 客户端日志打印 `音频 sha256 校验失败，删除下载文件`：服务端元数据的 sha256 与实际文件不一致，重新上传覆盖；
- 内置 `near.wav` / `end.wav` 通过 `/api/client/audio/:filename` 永远返回 404 是预期行为（内置音频的 `stored_path` 为 NULL），客户端优先使用打包资源。

### 5.5 后台改配置后客户端不生效

- 默认轮询 10 秒；如需更快生效，调小 `local_config.poll_interval_sec`（建议 ≥ 5 秒）；
- 检查服务端 `[audit_logs]` 中是否有 `config.update` 记录；
- 客户端日志中是否打印 `业务配置已更新到 vN`。

### 5.6 JWT_SECRET 忘改

- 启动时若 `JWT_SECRET` 仍是默认值，所有签发的 JWT 都是用同一把默认 key 签出来的；这意味着任何部署该代码的人都能伪造 Token。
- 修复：用 `openssl rand -hex 32` 生成 64 位十六进制串，写入 `JWT_SECRET`；重启 Node；**所有现存用户都需要重新登录**。

### 5.7 `disallowed host` / CORS 报错

- 当前实现是 `app.use(cors())`（全开），理论上不会出现 CORS 报错；
- 若你收紧过 CORS 中间件，需要把后台前端所在域名加白名单。

### 5.8 「不允许本地修改配置」灰色入口打不开

- 后台「配置编辑」把 `allow_local_edit` 改为 `true` 后保存；客户端在下一次轮询（≤ 10 秒）后重新打开配置窗口即可看到控件可用。

### 5.9 离线队列一直补传不上去

- 客户端日志若持续出现 `待同步队列第 N 条补传失败`：说明队列里有一条被服务器拒绝（HTTP 4xx），这种情况下客户端**不会清空队列**（避免覆盖已纠正为好的配置），需要：
  1. 关闭客户端；
  2. 删除 `client/cache/pending_updates.json`；
  3. 启动后客户端将以最新缓存 / 服务器版本为准运行。

### 5.10 备份与恢复

- 数据库：`mysqldump -u root -p homework_time > homework_time_YYYYMMDD.sql`；
- 上传音频：`tar czf audio_YYYYMMDD.tar.gz /www/homework_time/uploads/audio/`；
- 客户端缓存：可清空（`cache/`），客户端会自动重建。

## 六、版本升级

- 后端：在 `/www/homework_time` 下 `git pull`（如有版本管理），重新 `npm install`，`pm2 restart homework-time`；
- 前台：`cd web && npm install && npm run build`，无需重启 Nginx（站点直接读 `dist/`）；
- 数据库：`schema.sql` 已用 `DROP TABLE IF EXISTS`，**升级前请先备份**；如不希望丢数据，请手工迁移新表结构。
