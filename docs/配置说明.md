# 配置说明

> 适用版本：HomeworkTime v0.1
> 文档基于实际代码（`client/app/config.py` / `client/app/default_config.json` / `client/app/config_schema.json` / `server/src/utils/validate.js` / `server/src/default_config.json`）逐字段核对整理。

---

## 一、配置体系总览

系统采用**两份本地配置文件 + 一份服务器权威数据**的双轨模式：

| 文件 | 所在位置 | 同步关系 | 内容性质 |
|---|---|---|---|
| 业务配置（缓存） | `client/cache/business_config.json` | 服务器下发 → 本地缓存；本地保存成功后由 ApiClient 同步写回 | 业务配置 JSON（含 `version` 字段） |
| 业务配置（内置默认） | `client/app/default_config.json`（同副本 `server/src/default_config.json`） | 不参与同步；作为缓存缺失时的兜底 | 业务配置 JSON（仅占位） |
| 本机专属配置 | `client/local_config.json` | **不同步服务器** | 本机网络 / 设备 / UI 偏好 |

**业务配置的单一数据源是服务器**。客户端读取顺序为：

1. 服务器下发（`/api/client/config`，`ApiClient.poll`）
2. 本地缓存（`cache/business_config.json`，仅在断网或首次启动时使用）
3. 内置默认（`default_config.json`，兜底）

任意入口（远程后台 / 本地配置窗口）的保存都会通过 `PUT /api/config` 写回服务器，再由服务器返回最新 `version`，客户端据此刷新本地缓存。

### 离线行为

- 服务器不可达时，本地配置窗口的保存请求会被写入 `client/cache/pending_updates.json` 队列（结构为 `[{ts, config}, ...]），用户收到「已离线保存，联网后自动同步」的提示。
- 一旦网络 tick 检测到从离线恢复为在线（`ApiClient.heartbeat` 成功），会**先按序补传队列**，再立即拉取最新配置。
- 队列中任意一条 `PUT /api/config` 失败就停止（保持顺序），等待下次网络恢复后再次重试。

## 二、业务配置字段

业务配置必须符合 `client/app/config_schema.json` 与服务端 `server/src/utils/validate.js` 的双重约束。校验失败时 `PUT /api/config` 返回 `400 {error, errors[]}`，字段以下限/上限由实际校验逻辑决定。

### 2.1 字段总表

| 字段 | 类型 | 必填 | 默认值 | 含义 | 约束 |
|---|---|---|---|---|---|
| `evening_start` | string | 是 | `"18:30"` | 晚自习开始时间 | HH:MM 24 小时制；正则 `^([01]\d\|2[0-3]):[0-5]\d$` |
| `evening_end` | string | 是 | `"22:00"` | 晚自习结束时间 | 同上；当结束时间 < 开始时间时视为**跨天**（结束于次日）；**起止时间不允许相同** |
| `subjects` | array | 是 | 4 个示例科目 | 每天同一套的科目时间段（周一至周日相同） | 数组长度 0–10；每项含 `name` / `start` / `end` |
| `subjects[].name` | string | 是 | — | 科目名称 | 1–32 字符 |
| `subjects[].start` | string | 是 | — | 科目开始时间 | 同 HH:MM 正则 |
| `subjects[].end` | string | 是 | — | 科目结束时间 | 同 HH:MM 正则；且 `start != end` |
| `opacity` | object | 是 | 见下 | 三个窗口的整体透明度（`setWindowOpacity`） | 整体对象；子键均为 `number` |
| `opacity.main` | number | 是 | `0.85` | 主窗口透明度 | 0.2 – 1.0（含端点） |
| `opacity.ball` | number | 是 | `0.70` | 悬浮球透明度 | 0.2 – 1.0 |
| `opacity.config` | number | 是 | `1.00` | 配置窗口透明度 | 0.2 – 1.0 |
| `theme` | object | 是 | 见下 | 窗口主题色（自定义窗口颜色） | 整体对象；子键均为 `#RRGGBB` 字符串 |
| `theme.card` | string | 是 | `"#023E8A"` | 卡片背景色（主窗口/确认框自绘底色） | 正则 `^#[0-9A-Fa-f]{6}$` |
| `theme.accent` | string | 是 | `"#0077B6"` | 强调色（时间轴当前段高亮、确认框主按钮） | 同上 |
| `theme.timeline` | string | 是 | `"#03045E"` | 时间轴非当前条目底色 | 同上 |
| `allow_local_edit` | boolean | 是 | `true` | 是否允许本地配置窗口保存 | `false` 时本地配置窗口只读且入口置灰 |
| `idle_text` | string | 是 | `"课间休息"` | 落在晚自习区间但非任何科目段时显示的文字 | 1–64 字符 |
| `sound` | object | 是 | 见下 | 提示音相关（**仅全局一套**，不支持每科目覆盖） | 整体对象；子键限定 |
| `sound.enabled` | boolean | 是 | `true` | 提示音总开关 | `false` 时临近/结束音均不播放 |
| `sound.near_seconds` | integer | 是 | `60` | 临近提示音阈值（秒） | 1 – 3600 的整数（含端点）；本段剩余秒数 ≤ 该值时每秒播放一次 `near.wav` |
| `sound.near_audio` | string | 是 | `"near.wav"` | 临近提示音文件名 | 正则 `^[A-Za-z0-9._-]+\.wav$`；需存在于 `audio_files` 表 |
| `sound.near_enabled` | boolean | 是 | `true` | 临近提示音单独开关 | — |
| `sound.end_audio` | string | 是 | `"end.wav"` | 结束提示音文件名 | 同 `near_audio` 正则 |
| `sound.end_enabled` | boolean | 是 | `true` | 结束提示音单独开关 | — |

### 2.2 额外约束（业务规则）

下列规则来自 `server/src/utils/validate.js`，未在 JSON Schema 中显式声明但服务端强制校验：

1. **不允许未知顶层字段**（对应 `additionalProperties: false`）。提交未列出的字段会得到 `未知配置项: <key>` 错误。
2. **晚自习起止时间不允许相同**（`evening_start == evening_end` 会被服务端拒绝，返回 `起止时间相同` 错误）。24h 全开语义无意义且危险，故视为非法配置。
2. **科目时间段不能超出晚自习范围**。当 `evening_end > evening_start` 时，科目起止必须落在 `[evening_start, evening_end)`；跨天场景（`evening_end < evening_start`，等值已被禁止）下允许科目落在 `[evening_start, 24:00)` 或 `[00:00, evening_end)`。
3. **科目时间段两两不得重叠**。区间采用半开 `[start, end)` 判定。
4. **同一科目 `start` 不得等于 `end`**。
5. `subjects[].name` 不允许空字符串；不允许出现 `name` / `start` / `end` 之外的字段。
6. 提示音文件名后缀必须为 `.wav`，且只允许 `A-Za-z0-9._-`（防止路径穿越与非法字符）。
7. `theme` 三键（`card` / `accent` / `timeline`）必须为 `#RRGGBB` 格式（服务端会把合法值统一转为大写并回填缺失键的默认色）。

## 三、本机配置（local_config.json）

> 由 `client/app/config.py` 的 `LocalConfig` 类读写；**不参与与服务器的同步**，仅作用于本机。

### 3.1 字段总表

| 字段 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `server_base_url` | string | `"http://127.0.0.1:3000"` | 服务端 API 根地址（不带尾斜杠）。生产部署时改为宝塔面板上的域名或 IP（含协议与端口） |
| `client_token` | string | `""` | 客户端鉴权 Token；与服务端 `client_token` 表（id=1）的 `token` 字段一致；首次部署后由后台「客户端 Token → 重置」下发 |
| `poll_interval_sec` | integer | `10` | 心跳与轮询间隔秒数；建议 5–60，越大服务器压力越小但配置生效延迟越大 |
| `autostart` | boolean | `true` | 是否开机自启（写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`） |
| `ball_pos` | object \| null | `null` | 悬浮球屏幕坐标记忆 `{x, y}`；首次运行或拖动后由客户端自动持久化 |
| `ball_size` | integer | `64` | 悬浮球直径像素；建议 32–128（过小不易点击，过大会遮挡希沃一体机） |
| `device_uuid` | string \| null | `null` | 本机设备 UUID；首次启动由客户端随机生成并持久化，服务端以此识别教室设备 |

### 3.2 首次运行时

- 文件不存在 → `LocalConfig.load()` 会读取 `client/local_config.example.json` 的字段（去除 `_comment` 占位键），缺失字段用默认值补齐，自动生成 `device_uuid`，然后通过「临时文件 + `os.replace`」原子写回 `local_config.json`。
- 文件存在但字段缺失 → 按默认值补齐。
- 文件存在但 JSON 损坏 → 记录警告后回退默认值，不抛出。

### 3.3 示例（与 `client/local_config.example.json` 完全一致）

```json
{
  "server_base_url":     "http://127.0.0.1:3000",
  "client_token":        "",
  "poll_interval_sec":   10,
  "autostart":           true,
  "ball_pos":            null,
  "ball_size":           64,
  "device_uuid":         null
}
```

> 实际写入本机的 `local_config.json` 不包含以 `_` 开头的说明性键；`device_uuid` 在首次启动后会被替换为形如 `1f2c4b8a-...` 的 UUID 字符串。

## 四、配置修改的两种途径

业务配置与本机配置都可以被修改，但**业务配置的「单一数据源」是服务器**，任何修改最终都会通过 `PUT /api/config` 落地到服务器再回灌到本地缓存。

### 4.1 远程后台（推荐）

1. 浏览器打开后台 → 「配置编辑」。
2. 修改任意字段 → 「保存」。
3. 前端调用 `PUT /api/config`（`Authorization: Bearer <jwt>`），服务端校验 + `version+1` + 写审计日志 + 返回完整新配置。
4. 所有在线客户端在下一次轮询（≤ `poll_interval_sec`）看到 `version` 增大，触发 `GET /api/client/config` 拉新配置并 `apply_config()`。

### 4.2 本地配置窗口（悬浮球右键确认 → 「确定」）

入口：
- 悬浮球右键 → 确认对话框 → 打开配置窗口（`ConfigWindow`）。
- 系统托盘 → 右键菜单 → 「打开配置」。

行为：
- 窗口打开时拉取服务端音频列表（如失败回退本地），填充音频下拉框。
- 业务配置保存链路：
  1. `validate_subjects()` 前置校验（≤10 行、HH:MM、`start != end`、名称非空）+ `validate_theme()`（三键 #RRGGBB）。
  2. `push_config()` → `PUT /api/config`（`X-Client-Token`）：
     - 成功：调用 `apply_config()` 立即使 UI/调度器生效，提示「✓ 保存成功」。
     - 网络层失败 / 超时：`save_pending()` 写入 `cache/pending_updates.json`，提示「已离线保存，联网后自动同步」。
     - HTTP 4xx/5xx（Token 无效、校验失败）：弹窗提示，**不入队**。
- 悬浮球尺寸（`ball_size`）直接写 `local_config`，**不走服务器**。
- 关闭 `allow_local_edit`：窗口打开即提示「管理员已禁止本地修改配置，请使用远程后台」，全部控件置灰、保存按钮禁用。

### 4.3 `allow_local_edit` 开关

| 后台 `allow_local_edit` | 本地配置窗口 | 后台配置编辑 | 说明 |
|---|---|---|---|
| `true` | 可读写、保存 | 可读写 | 默认形态 |
| `false` | 只读置灰 + 顶部红条提示 | 可读写 | 强制改用远程后台 |

切换方式：远程后台「配置编辑」勾选切换（写业务配置）；客户端在保存到服务器后会立即在本地重新读取最新业务配置并刷新窗口态。

## 五、提示音说明

> 实现见 `client/app/audio.py` / `client/app/api_client.py` / `server/src/routes/audio.js`。

### 5.1 全局一套提示音（不支持每科目覆盖）

业务配置 `sound` 段只存在一份，与晚自习中具体科目无关。提示音触发由 `client/app/scheduler.py` 的 `get_sound_actions()` 计算。

| 音频 | 触发时机 | 文件 |
|---|---|---|
| 临近提示音 | 当前科目段剩余秒数 `> 0` 且 `≤ sound.near_seconds` 时**每秒**播放一次 | `sound.near_audio`（默认 `near.wav`） |
| 结束提示音 | 上一 tick 仍在某个科目段内、且该段结束点刚被本 tick 跨越时播放**一次** | `sound.end_audio`（默认 `end.wav`） |

进入新科目段时 `prev_key` 自动变化，结束音**不会**重复触发；段内每次 tick 都会重算临近音，符合「每秒响一次」的语义。

### 5.2 内置音频与后台上传

| 类别 | 文件 | 来源 | 后台能否删除 |
|---|---|---|---|
| 内置 | `near.wav` / `end.wav` | 随客户端打包在 `client/resources/sounds/`；服务端 `audio_files` 表中 `is_builtin=1`、`stored_path=NULL`（实际文件不入库） | **否**（`DELETE /api/audio/:id` 对内置返回 `400 内置音频不可删除`） |
| 上传 | 任意合法 wav 文件名 | 管理员通过后台「音频管理」上传；物理文件存 `server/uploads/audio/<filename>`，DB 中 `stored_path = "uploads/audio/<filename>"` | **可** |

### 5.3 同名覆盖规则

- 后台上传 `near.wav` 或 `end.wav`：在 `audio_files` 表发生冲突时走 `ON DUPLICATE KEY UPDATE`，刷新 `stored_path / size / sha256 / uploaded_by`，**但 `is_builtin` 保持为 1**（覆盖后内置行仍不可删）。物理文件被新文件覆盖后，客户端按 sha256 校验即可从服务端下载新版（覆盖了原内置资源）。
- 后台上传非内置同名音频：完全覆盖。
- 客户端只下载当前 sha 与本地不一致的音频文件；内置音频会**优先使用打包资源**，仅当服务端有「覆盖版」且 sha 与内置不一致时才会落到下载逻辑。

### 5.4 文件名合法字符

`^[A-Za-z0-9._-]+\.wav$`——后缀必须 `.wav`，主体仅允许字母/数字/下划线/连号/点。

### 5.5 客户端解析顺序

`AudioPlayer.play(wav_name)` 按以下顺序解析路径：
1. 绝对路径（`wav_name` 为绝对路径且文件存在）；
2. 下载缓存目录 `client/cache/sounds/<wav_name>`；
3. 内置资源 `client/resources/sounds/<wav_name>`（PyInstaller 打包时映射到 `sys._MEIPASS/resources/sounds/`）。

非 Windows 平台无 `winsound` 时 `play()` 安全降级（仅记录日志，不抛错）。

## 六、首次运行引导流程

入口条件：`local_config.server_base_url` 或 `local_config.client_token` 任一为空（`client/app/main.py::_needs_guide`）。

1. 弹出 `GuideWindow`（模态、固定 460×330、置顶）：
   - **服务器地址**输入框（默认填 `local_config` 当前值）——例如 `http://192.168.1.10:3000`；
   - **客户端 Token**输入框（密码模式）；
   - 「测试连接」按钮：调用 `GET {base_url}/api/client/config`，header 携带 `X-Client-Token`，超时 5 秒：
     - HTTP 200 + 返回 `version` → 「✓ 连接成功（配置版本 vN）」；
     - 超时 → 「连接超时（5 秒），请检查网络」；
     - 连接错误 → 「无法连接服务器，请检查地址与端口」；
     - HTTP 401/403 → 「Token 无效（HTTP %s）」；
     - 其他 4xx/5xx → 「服务器返回错误（HTTP %s）」；
   - 「保存并进入」按钮：将 URL/Token 写回 `local_config` 后继续启动；
   - 「跳过（离线模式）」按钮：直接进入，客户端只读取内置默认配置，**所有保存会全部进入离线队列**。
2. 完成引导后回到主启动流程：
   - `setup_logging()`（按天滚动本地日志到 `client/logs/app_YYYY-MM-DD.log`，默认保留 30 天）；
   - 应用 `autostart` 注册表项；
   - 构建 `AppController`（主窗口 + 悬浮球 + 托盘 + 网络同步定时器）；
   - 启动后立即执行一次网络 tick：心跳 + 拉配置 + 音频保障。

## 七、目录与缓存文件

| 路径 | 用途 |
|---|---|
| `client/local_config.json` | 本机专属配置（首次运行后生成） |
| `client/local_config.example.json` | 本机配置示例模板（参考用，不直接生效） |
| `client/local_config.preset.json` | 打包预设（**仓库不含，已 `.gitignore`**；按需从 example 复制并填好 `server_base_url` / `client_token`，随 exe 分发到目标机） |
| `client/cache/business_config.json` | 业务配置缓存（含顶层 `version` 字段） |
| `client/cache/pending_updates.json` | 离线保存队列；联网后自动补传并删除 |
| `client/cache/sounds/<filename>` | 从服务端下载的音频缓存 |
| `client/resources/sounds/near.wav`、`end.wav` | 内置提示音（随客户端打包） |
| `client/logs/app_YYYY-MM-DD.log` | 本地运行日志（按天滚动，默认 30 天） |

> `client/cache/` 目录由 `LocalConfig` / `AppConfig` / `ApiClient` 自动创建，**无需手工准备**。
